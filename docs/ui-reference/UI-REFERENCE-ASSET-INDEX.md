# فهرس أصول مراجع الواجهة — Aghbari Commerce

> **النطاق:** صور مرجعية تاريخية/تصميمية فقط. لا تُحمّل هذه الملفات ضمن أصول المتجر التي تُعرض للمستخدم، ولا تُعامل بيانات أو أسماء أو أرقام الصور على أنها بيانات تشغيلية حقيقية. تستخدم الشاشة المرجعية لتوجيه التصميم وسلوكيات حالات الواجهة، لا لاستنساخ الهوية القديمة أو بياناتها.

## جرد فعلي

- الصور الموجودة في هذا المسار على `main`: **89**.
- كتل Git الفريدة بحسب SHA-1: **85**.
- ملفات صور مكررة تماماً بالبايت: **4** (أربعة أزواج).
- المصدر: [المجلد على GitHub](https://github.com/Report-Engainall/aghbari-store/tree/main/docs/ui-reference).
- فهرس الشاشة هذا لا يعلن أن أي ميزة في التطبيق قد نُفذت؛ إنه يحدد عائلة المرجع وعلاقته المحتملة بالمسارات التي يجب مراجعتها وتنفيذها واختبارها.

## سياسة استخدام الصور

1. اجمع الصور حسب **عائلة الشاشة وسلوكها**؛ نفّذ العائلة مرة واحدة، لا صورةً بصورة.
2. عند الدمج، حافظ على واجهة العلامة التجارية الحالية **الأغبري / Aghbari Commerce**؛ أي علامة قديمة داخل الصورة مصدر إلهام بصري فقط ولا تُعاد إلى المنتج.
3. انقل من الصور البنية الواجهةية والسلوك المستفاد فقط. لا تنسخ أسماء العملاء، رموز الأصناف، مبالغ الإيرادات أو بيانات المخزون التي تظهر داخل الصور.
4. استخدم لغة عربية وRTL، responsive breakpoints، وصول لوحة المفاتيح، وحالات loading/empty/error/success/permission-denied. لا تُظهر نجاحاً وهمياً عندما لا يوجد Backend/RPC فعلي.
5. تُحفظ الصور في `docs/ui-reference/` كسجل مرجعي، وليس في `public/` أو bundle الإنتاج.
6. يشار إلى كل تكرار SHA في خانة «النسخة المطابقة»؛ يمكن الاحتفاظ بالاسم التاريخي للرجوع والتتبع، لكن لا تنشئ صفحة تطبيق ثانية بسببه.

## خريطة عائلات الشاشة

| عائلة الشاشة | ما نتعلمه من المراجع | ما يجب مطابقته داخل التطبيق | شرط التنفيذ |
|---|---|---|---|
| لوحة الإدارة والتنقل | مجموعات وحدات قابلة للفهم، مسار وصول واضح | `src/components/admin/AdminShell.tsx` و`src/App.tsx` | الروابط والصلاحيات يجب أن تتوافق مع route guards الفعلية |
| الطلبات | كانبان + قائمة + تاريخ حالة | `src/pages/admin/AdminPages.tsx` وواجهات العميل ذات الصلة | لا اعتماد للكمية عبر blur؛ تحديث حالة آمن خادمي |
| العملاء والأجهزة | تصفية العملاء وحالة الأجهزة/تغيير الجهاز | صفحات العملاء والأجهزة الحالية | لا إيقاف جلسة/تبديل جهاز بلا تحقق Server-side |
| الكتالوج/التصنيفات/الأسعار | tabs مميزة، جدول أسعار الجملة والتجزئة والأساسي | صفحات Catalog/Pricing وقواعد التسعير | السعر الأساسي جذر الاحتساب؛ حذف القواعد يعيد القيم المشتقة للأساسي؛ تحقق من RLS |
| العروض والمظهر | عروض محدودة زمنياً، ألوان ومساحات مريحة | Settings/Theme وكتالوج المتجر إن وجد | لا تُعرض حملة عميل على أنها نشطة من دون قواعد وتواريخ محفوظة |
| الاستيراد الموحد | اختيار ملف، اكتشاف/ربط الأعمدة، قوالب بإصدارات، DQS، سياسة تكرار، سجل | `src/pages/admin/AdminPages.tsx`, `src/lib/csvImportPipeline.ts`, migrations | استيراد فعلي فقط؛ CSV حالياً هو المسار المقروء تدريجياً، Excel/PDF للمراجعة حتى ربط parser؛ لا دمج Live DB شكلي |
| Onyx Pro والمطابقة | بيئة منفصلة، Dry Run، نتائج مطابقة وسجل عمليات | مسار تكامل مستقل / جداول snapshot منفصلة | لا تعديل على مخزون التشغيل من ملفات Onyx قبل مراجعة واعتماد صريح |
| التحليل والتوصيات | KPIs، رسوم، مخزون راكد، توقعات نفاد، أثر/ثقة | منفصل عن شاشة المتجر؛ يُبنى من بيانات موثوقة فقط | الأرقام deterministic من SQL؛ LLM يفسر ولا يحسب ولا يختلق عند نقص التاريخ |
| التنبيهات والمهام والمساعد | بطاقات قابلة للقراءة، أولوية ومسؤولية وسياق | شاشات تنبيهات ومهام ومساعد | كل إجراء مرتبط بعملية API حقيقية وسجل تدقيق |
| صحة النظام/الأخطاء/التدقيق | فحوص خدمة، قائمة أخطاء، سجل نشاط | صفحات المراقبة/التدقيق الحالية إن وجدت | لا تفترض أن اتصالاً أو صفراً من النتائج يعني أنه لم تقع أخطاء |
| الأدوار والصلاحيات | مصفوفة صلاحيات حسب الدور | Route guards + RLS + RPC grants | فرض الصلاحية في الخادم لا في UI فقط |
| ملكية المتجر وGitHub | بيانات مالك وإعدادات ربط/تغييرات | إعدادات مخصصة عند توفّر تكامل مصرح | لا تحفظ مفاتيح API نصاً خاماً ولا ترفع أسرار إلى الواجهة |
