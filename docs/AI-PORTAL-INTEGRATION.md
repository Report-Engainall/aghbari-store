# قرار تكامل بوابة الذكاء الاصطناعي داخل Aghbari Commerce

**الحالة:** توجيه تنفيذي حاكم، أحدث من أي صياغة سابقة تصف البوابة على أنها تطبيق أو نظام معزول.

## القرار

بوابة الذكاء الاصطناعي وحدة داخل تطبيق الأغبري نفسه، وليست منتجًا مستقلًا أو تطبيقًا منفصلًا أو نشرًا منفصلًا. تستخدم React Router وواجهة الإدارة المشتركة وAuthProvider والجلسة والمؤسسة النشطة نفسها.

## المسارات داخل التطبيق

- `/admin/ai`: مدخل مركز الذكاء الاصطناعي.
- `/admin/ai/reports`: سجلات التقارير.
- `/admin/ai/alerts`: التنبيهات.
- `/admin/ai/tasks`: المهام.
- `/admin/ai/assistant`: المساعد التشغيلي.

تظهر هذه المسارات في التنقل الإداري ذاته، وتخضع إلى بوابة الصلاحيات نفسها المستخدمة داخل لوحة الإدارة. لا يوجد تسجيل دخول مستقل للمساعد.

## حدود البيانات والأمان

- تعني تسمية جداول `ai_*` تنظيم بيانات التحليل وعقودها، لا عزل واجهة الذكاء الاصطناعي عن التطبيق.
- كل قراءة لهذه السجلات تُقيَّد بالمؤسسة النشطة، وتظل RLS وصلاحيات الخادم هي مصدر فرض الحدود.
- لا يمنح دمج الواجهة إذنًا بتجاوز سياسات الوصول، أو الكتابة المباشرة في الطلبات والمدفوعات والمخزون، أو إرسال بيانات العملاء إلى نموذج خارجي.
- لا تُعرض أرقام تجريبية باعتبارها نتائج فعلية. تُظهر الشاشة أخطاء المصادر عند تعذر تحميلها.

## حالة المساعد الحالية

تم ربط مسار مساعد تشغيلي داخل التطبيق لعرض ملخصات من سجلات التقارير والتنبيهات والمهام المحفوظة. هذه النسخة لا تدّعي أنها نموذج توليدي؛ لا يوجد مزود نموذج توليدي مفعّل داخلها، ولا تُرسل بيانات إلى مزود خارجي. تفعيل نموذج فعلي يتطلب تنفيذ تكامل خادمي آمن مستقل عن واجهة المستخدم، مع تحديد سياسة البيانات والميزانية والصلاحيات واختبارات الخصوصية.

## قبول التنفيذ

لا يُعدّ المساعد جاهزًا كنموذج ذكاء اصطناعي توليدي قبل تهيئة مزود خادمي وإثبات عمله؛ لكن واجهته متكاملة مع التطبيق الحالي وليست بوابة منفصلة. يجب أن ينجح بناء التطبيق وفحص عقود الواجهة، وأن تكون المصادر الفعلية مقيّدة بالمؤسسة، وأن تُعرض الأخطاء دون إخفاء.
